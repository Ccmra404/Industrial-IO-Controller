# Industrial IO Controller

工业多通道 IO 控制器项目仓库，用于集中管理产品需求、硬件设计、嵌入式固件、测试记录和生产资料。

> **项目状态：** 仓库骨架已建立，具体硬件规格、器件选型、原理图、PCB 和固件以经过确认并提交的项目文件为准。本仓库当前不预设 IO 通道数量、电气参数、主控型号或通信协议。

## 项目目标

- 建立可追溯的产品需求与技术决策记录。
- 统一管理嘉立创 EDA 等工具产生的原生硬件设计文件。
- 管理嵌入式固件源代码、构建说明和版本记录。
- 记录硬件 bring-up、功能、可靠性及回归测试结果。
- 通过 Issue 和 Pull Request 进行任务分解、设计讨论与变更审核。

## 当前需要确认的设计输入

以下内容应通过需求文档或 Issue 明确，不应在缺少依据时直接写成已确定规格：

- IO 类型、通道数量及每路输入/输出电气范围。
- 输入阈值、输出驱动能力、负载类型及保护方式。
- 电源输入范围、功耗预算、反接与过流保护要求。
- 通道间、接口间及电源侧的隔离需求。
- 通信接口、协议、连接器和引脚定义。
- 主控 MCU、时钟、调试与固件升级方式。
- 工作温度、EMC/ESD/浪涌环境和安装方式。
- 安全要求、测试方法及验收标准。

## 协作流程

1. 在 GitHub Issues 中提出需求、缺陷或设计任务。
2. 设计变更在独立分支中完成，分支命名和提交规范见 [CONTRIBUTING.md](CONTRIBUTING.md)。
3. 提交 Pull Request，说明变更原因、影响范围、验证方法和未完成事项。
4. 硬件变更应检查原理图/ERC、PCB/DRC、器件封装、接口、电源及保护设计。
5. 固件变更应提供构建方式、测试结果和兼容性说明。
6. 未完成必要验证的设计不得标记为已验证或可量产。

## 重要说明

- 请提交可编辑的 EDA 原生工程文件；不要只提交截图或 PDF 而丢失源工程。
- 不要提交密码、访问令牌、私钥或其他敏感信息。
- 生产文件应标明硬件版本、生成工具版本和生成日期。
- **公开仓库不等于自动授予开源许可。** 当前仓库未添加 LICENSE；授权方式需由项目维护者确认后再添加。
- 本仓库的目录和模板不代表任何具体电气参数或安全认证已经完成。
